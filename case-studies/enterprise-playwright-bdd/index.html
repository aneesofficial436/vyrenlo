Challenge

Regression that cannot keep up

A sprawling enterprise web app outgrew manual regression. Teams needed traceability, reuse, and parallel runs without constant locator thrash.

Solution

Playwright-BDD at scale

playwright-bdd, a pinned framework submodule, ElementResolver vocabulary, and Azure DevOps publishing—owned by QA, automation, and platform together.

Outcome

Confidence to merge

PR validation that highlights new failures, rich traces for triage, and a repo-shaped runbook for humans and coding agents.

Architecture

Separate “what to test” from “how to drive the UI”

QA ships scenarios; test automation ships vocabulary. CI checks out the framework branch that matches the application release line.

  • Generated .features-gen/ specs treated as build output—never edited by hand
  • Logical element names via ElementResolver—not scattered selectors in features
  • Allure, JUnit XML, traces, and step-timing reports for fast triage

Design lessons

What we would repeat on the next program

  • Separate what to test from how to drive the UI—QA velocity without everyone touching locators
  • Treat generated Playwright specs as build artifacts
  • Version the framework with the product—explicit CI branch checkout over a stale submodule pin
  • Invest in one step text and one logical element name; indexes make that searchable
  • Classify failures before coding—locator, step, config, or product defect
  • Embed agent skills in the repo so onboarding is playbook-driven
  • Tags are execution contracts—they control parallel runs and reporting dimensions
